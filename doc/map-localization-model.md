# 小地图实时定位模型（颜色不变结构特征 + CNN）

> 结论先行：本项目给你**能跑、带进度条、推理 < 1s** 的训练 / 推理代码；
> 但**准确率的瓶颈不在"能不能实时"，而在"有没有可信的训练数据"**。纯合成数据只能让模型
> 学会形状特征，难以达到高精度；**要真正准确，建议从游戏里采集"真实小地图 + 已知玩家位置"成对数据**。

---

## 1. 为什么不能用颜色

* 同一张地图在不同电脑上配置/渲染不同，**颜色会变**（之前 SIFT/ORB/NCC 用颜色/灰度全部失败，准确率 0）。
* 但地图的**纹理/结构（边缘、道路、建筑、海岸线）基本不变**。

因此只使用**颜色不变结构特征**：

```
通道0：多通道梯度最大值        （任何颜色通道的强边缘都保留，对色相/饱和变化鲁棒）
通道1：局部二值模式 LBP        （对亮度/对比度单调变化稳健）
通道2：Laplacian 绝对值        （高频纹理）
```

每个通道按样本 z-score 归一化。

---

## 2. 关键：尺度不变（每台电脑缩放比例不同）

小地图是原地图经**缩放**后的版本，且**每台电脑缩放比例不同**。不做尺度处理怎么都对不上：
* **训练覆盖极宽尺度**：随机区域宽 `rw` 取对数均匀采样 `[80, 6000]` 世界px，模型见过
  "大幅放大 / 大幅缩小"的小地图，从而**尺度不变**。
* **模型同时输出 `rw`**：推理时直接预测当前小地图的世界覆盖宽度，无需固定缩放。

所以训练脚本天然是尺度不变的；关键是**不要用固定缩放去匹配，而是搜索/预测尺度**。

## 3. 训练方案（合成增强，从大地图自举）

模型 `Localizer`（CNN）：输入 `128×128×3` 结构特征 → 输出 `32×32` 位置热图（对大地图分格软分类）
`+` 区域尺度 `rw`（预测小地图覆盖的世界宽度）。

训练样本在训练循环内从 `level_13` 大地图**即时生成**：
* 随机中心 `(cx,cy)`、随机区域尺度 `rw`；
* 只采"岛屿内容占比足够"的区域；
* 特征域增强：**圆形裁剪 + 边缘晕影 + UI 图块（玩家箭头/标签条/图标）+ 小旋转**，
  模拟小地图的圆形刻度盘、晕影、去不掉的 UI —— 让模型学会忽略它们。

速度优化：大地图结构特征**一次性预计算**（`FEAT_RES=2048`），采样时只 crop + resize，很快
（单个 epoch 约 5s / 3000 样本）。**带 epoch 级 + batch 级 tqdm 进度条**。

---

## 4. 实时推理（< 1s）

`localize_minimap_model.py`：
1. 小地图 -> 结构特征（128×128）。
2. CNN 单次前向（毫秒级）→ 热图 argmax 给粗略格子（每格 256 世界px）+ 预测 `rw`。
3. 可选：在粗定位附近做**小范围结构 NCC 细定位**（仅局部窗口，快）。实测每张图
   `0.16~0.42s`，满足 <1s。

输出：每张图贴到大图的结果图 `result_N.png` + `report.json`（世界坐标 / 瓦片 / 归一化）。

## 5. 运行方式（rocokingdom_dev_gpu）

```powershell
$py="D:\Dev\anaconda3\envs\rocokingdom_dev_gpu\python.exe"

# 训练（可调 --epochs / --train-samples；默认约几分钟）
& $py tools/train_localizer.py --epochs 60 --train-samples 20000 --out model/localizer.pt

# 推理（<1s/张）
& $py tools/localize_minimap_model.py --ckpt model/localizer.pt
```

常见参数：`--rotate`（若小地图会跟随角色朝向旋转则开启，默认朝北/关）、
`--batch`、`--lr`、`--val-samples`。

## 6. 现状与建议（重要，诚实说明）

已确认：**训练跑得动、有进度条、推理 <1s**。但在我本地短训练（约 5 epoch / 3000 样本）下，
模型仅略高于随机（热图轴命中率 ~8%，中位误差 ~2000+ 世界px）。这说明：

* 纯合成数据 + 全图全局定位，模型收敛慢，**精度不足以直接上线**；
* 我反复验证过：**传统 CV（SIFT/ORB/NCC，含尺度/旋转）对真实小地图也失败**（得分 0.3~0.4，
  峰值落在错误位置），而对"合成模拟小地图"却能准确定位。差异说明真实小地图与这张
  level_13 大地图的**对应关系（尺度/旋转/渲染/UI）** 需要先校准，或需要**真实成对标签**。

**最能提升准确率的做法（强烈建议）**：
1. **从游戏里采集真实成对数据**（最准）：截图小地图的同时记录玩家在大地图上的真实世界坐标
   （若你能拿到游戏内坐标协议/罗盘 → `docs/map-awareness.md`），连同小地图覆盖的世界半径 `rw`，
   存成 `minimap路径,cx,cy,rw` 的 CSV，然后用：
   ```powershell
   & $py tools/train_localizer.py --real-csv data/pairs.csv --epochs 60 --out model/localizer.pt
   ```
   脚本已支持 `--real-csv`。真实成对数据能同时教会模型**每台电脑的真实缩放**与**真实渲染差异**——
   这是合成数据做不到的。
2. 或先给我 **4 张真实小地图的真实位置**（哪怕大致区域），我据此校准尺度/旋转并构建更贴近
   游戏的合成数据，训练才能收敛到可用精度。

一句话：**代码给你了，实时 <1s 做到了；但"准不准"取决于你能否提供真实成对样本或真实坐标来校准。**
