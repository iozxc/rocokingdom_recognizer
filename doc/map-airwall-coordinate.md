# 地图空气墙坐标系与提取说明

> 适用范围：assets/mapsrc 下的 `level_10/11/12/13` 四张拼图（同一岛屿、不同分辨率）。
> 含义：把整片可通行区域（岛屿本体 + 可涉水浅滩）的最外圈轮廓提取成一条**闭合连续折线**，
> 这条线就是"空气墙"——再往外就是不可进入的虚空。

---

## 1. 坐标系是怎么定义的（你要求的"市面上最常见的定义方式"）

这里采用 **Web-Mercator 风格的瓦片金字塔（slippy map）** 坐标系，这也是 Google Maps、
OpenStreetMap、高德等在线地图通用的约定。你的文件命名 `level_10_508_511_508_511.png`
本身就完全符合这套约定。

### 1.1 三个基本量

| 量 | 含义 | 说明 |
| --- | --- | --- |
| `zoom / level`（层级 L） | 世界的精细度 | 整数，越大越清晰 |
| `tileX` | 瓦片列号 | 0 开始，**向右（东）增大** |
| `tileY` | 瓦片行号 | 0 开始，**向下（南）增大** |

在层级 L，整个世界被切成 `2^L × 2^L` 个瓦片，每个瓦片 `256 × 256` 像素。
所以：

```
世界像素大小 = 256 × 2^L                     // 单位：px
tileX, tileY ∈ [0, 2^L)
```

### 1.2 像素级坐标（真正落到画面上用的）

一个点的完整坐标可以用"瓦片号 + 瓦片内像素"表示：

```
worldX = tileX × 256 + (瓦片内像素 x)
worldY = tileY × 256 + (瓦片内像素 y)
```

`(worldX, worldY)` 叫做**全局像素坐标**：

* 原点是整个世界左上角 `(0,0)`；
* `+worldX` 向右（东）、`+worldY` 向下（南）；
* 方向与 PNG 图片像素完全一致——**不需要上下翻转**，直接拿去做叠加、裁剪、Canvas 绘制都最不容易出错。

### 1.3 你的这张图对应到哪

`level_10_508_511_508_511.png` 是把 `tileX ∈ [508,511]`、`tileY ∈ [508,511]` 的
**4×4 = 16** 个瓦片拼成的 `1024 × 1024` 图像。

设拼图内像素坐标为 `(i, j)`（`i` 向右、`j` 向下，范围 `0..1023`），则换算关系为：

```
tileX = 508 + floor(i / 256)        tileY = 508 + floor(j / 256)
tile内x = i % 256                    tile内y = j % 256

worldX = 508×256 + i = 130048 + i
worldY = 508×256 + j = 130048 + j
```

验证（本图空气墙外接矩形）：`i ∈ [74,912]` → `worldX ∈ [130122, 130960]`；
`j ∈ [170,816]` → `worldY ∈ [130218, 130864]`。均在 `[130048, 131071]` 区间内，合理。

### 1.4 同一张图跨层级怎么换算

4 张图内容完全一样、只是分辨率不同，对应同一个地理区域。换算规则：

* 从层级 L 到层级 L+k：图像放大 `2^k` 倍；`world` 像素坐标也 `× 2^k`。
* 归一化坐标 `(i/宽, j/高)` 在任意层级相同。
* 瓦片号从 L 到 L+k：`tileX_{L+k} = tileX_L × 2^k`（这正是你看到 map 文件夹里
  508→1016→2032→4064 翻倍的原因）。

因此只要存一份（例如层级 10 的全局像素，或归一化坐标），就能无损换算到 11/12/13 层。

### 1.5 关于本项目历史脚本的一个坑（已替你对齐到标准）

`tools/fetch_17173_map_tiles.py` 里用的约定是"x 向下（行）、y 向右（列）"，
和上面的标准恰好是**转置**的。本图的 `508..511` 两轴完全对称，所以转置不影响结果；
但为了符合"市面上最常见"的标准，本脚本和新文档一律使用标准约定
`tileX=列/右`、`tileY=行/下`，并在数据里同时给出多种坐标以免混淆。

## 2. 空气墙是怎么提取出来的

1. **分割背景**：虚空是均匀深蓝 `(31,55,99)`。判定"不是虚空"（即地图内容）的条件是
   RGB 颜色距离 `> 70`。之所以取 70 而不是更小的值，是为了让边界**正好落在淡蓝色浅滩
   （light-blue）的外沿**，把浅滩外圈那层"暗青过渡晕/发丝轮"排除掉——这正是你要求的
   `以地图淡蓝色为边`。若用 48，边界会连暗色晕一起算入、往外多飘几像素、看起来偏糊。
2. **取最大连通域**：只保留面积最大的那块（本图 351,167 px，其余连通域都 ≤8 px，是噪点）。
3. **填洞**：从外部洪泛填充，把内部湖/漩涡填成实心，使外轮廓是单一闭环。
4. **边界追踪**：Moore 邻域追踪，得到最外圈像素折线（原始 2889 个点）。
5. **简化（Douglas-Peucker）**：控制点数。

> 备注：默认边界取的是"浅滩（可涉水）也包含在内"的最外圈。如果你只要**干地**边界，
> 把 `--thresh` 往上调，或改成只对"陆地色"做 mask 即可。

## 3. 输出文件与数据 schema

运行：

```powershell
python tools/extract_map_airwall.py
```

默认输出到 `assets/mapdata/`（level 10 由提取脚本直接算，level 11/12/13 由导出脚本从 level 10 等比换算）：

| 文件 | 内容 |
| --- | --- |
| `airwall_level{L}.json` | 元信息 + 4 种坐标系折线 + 原始全量折线（L=10/11/12/13） |
| `airwall_level{L}.geojson` | 标准 GeoJSON Polygon（本地平面像素坐标系，非 WGS84） |
| `airwall_level{L}.svg` | 矢量路径（可直接拖进浏览器/设计软件） |
| `airwall_level{L}_preview.png` | 对应层级原图上叠红色空气墙，用于人工核对 |

`airwall_level{L}.json` 结构：

```jsonc
{
  "meta": {
    "level": 10,
    "tile_size": 256,
    "tile_range": { "tileX": [508,511], "tileY": [508,511] },
    "world_px_size_at_level": 262144,
    "coordinate_system": "slippy-map ...",
    "raw_contour_points": 2889,
    "simplified_points": 218,
    "simplification_sweep_points": { "0.5": 988, "1": 456, "2": 218, "3": 110, "5": 65 }
  },
  "polygon": {
    "image_px":        [[x,y], ...],                    // 拼图内像素 0..1023
    "world_px_level":  [[x,y], ...],                    // 全局像素(层级10)
    "tile_px":         [[tileX,tileY,内x,内y], ...],    // 瓦片+内像素
    "normalized":      [[u,v], ...]                     // 0..1，跨层级通用
  },
  "full_resolution_polygon": { /* 未简化全集 */ }
}
```

所有折线都是**闭合**的（首尾相连）。JSON 里的 `image_px` 最方便直接叠加到这张图上。

## 4. 你问的第一点：坐标点太多，画起来是不是很难？怎么解决？矢量化怎么定义？

**结论：不难。** 一张闭合多边形在渲染时**只画一次**，无论它是 65 点还是 2889 点，
GPU/Canvas 都是一次 `fill`/`stroke` 调用，点数不会让绘制变"慢很多"。2938 个顶点对任何现代
渲染器而言都是极小的数据。真正会让人觉得"多"的是**存储、网络传输、编辑、二次加工**时的冗余，
这些才是简化要解决的问题。

### 解决方案（按用途选）

1. **Douglas–Peucker 简化**（已内置）。

   | eps(px) | 点数 | 适合 |
   | --- | --- | --- |
   | 0.5 | 988 | 几乎无损失 |
   | 1 | 456 | 精细 |
   | **2** | **218** | **推荐，画图/前端** |
   | 3 | 110 | 更省，仍贴合 |
   | 5 | 65 | 便宜碰撞/概览 |

2. **保角简化**：若希望更少点又不丢尖锐海角，用 **Visvalingam–Whyatt** 或"径向距离 + 保留显著凸角"，
   比纯 Douglas-Peucker 更贴合图纸。
3. **曲线矢量化**：把折线换成 **Catmull-Rom / B-spline / 贝塞尔**，用几十个控制点加插值就能还原平滑海岸线。
   SVG 里直接写成 `M ... C ... Z`（三次贝塞尔）即可，文件更小、视觉更平滑。
4. **矢量的标准定义**：见 `airwall_level10.svg`——
   `<path d="M x,y L x,y ... Z" fill=... stroke=.../>`，一个 `d` 属性就是一条矢量路径，
   "矢量"的本质就是**有序顶点 + 闭合规则 + 填充/描边样式**，它天生就是矢量的，不是点阵。

所以：**画图用 SVG 矢量路径（few 点 + 可选曲线）；要最省就加贝塞尔；要可编辑就保留 EPS≈2 的 218 点多边形。**

## 5. 你问的第二点：能不能不用坐标、用别的什么？

"坐标"是描述几何最基本的表示；所谓的"替代"其实是**同一几何的不同编码/存储方式**，各有用武之地。

| 方案 | 是什么 | 优点 | 适用 |
| --- | --- | --- | --- |
| **碰撞掩码（bitmap mask）** | 一张 1-bit 图，1=可通行、0=墙 | 判定"某点是否在地图内"＝采样一个像素，O(1)，最省事 | 游戏运行时碰撞 |
| **RLE（行程编码）** | 按行压缩掩码 | 比裸掩码小 | 存碰撞区 |
| **符号距离场 SDF** | 每像素存"到边界的距离" | 平滑、支持"距边界 X 米"查询、轻松做扩张/收缩/路径规划；不是坐标但可直接用 | 移动平滑、UI 高亮、碰撞缓冲 |
| **曲线/样条** | 少量控制点 + 插值 | 极小，平滑 | 绘制、压缩 |
| **隐式/生成参数** | 若地图由程序生成，存生成参数即可 | 一个参数就描述整条海岸线 | 程序化地图 |
| **GeoJSON / WKT** | 依然是坐标但为标准格式 | 生态通用 | 和地图工具、引擎互操作 |
| **Marching Squares** | 直接从掩码生成亚像素平滑轮廓 | 比像素级更光滑 | 想得到更好看的轮廓 |

**选型建议**

* 要**画出来/给人看** → SVG 矢量路径（few 点 / 贝塞尔）。
* 要**游戏内碰撞判断"能不能走"** → 1-bit 碰撞掩码或 SDF，避开坐标（反而更快）。
* 要**换引擎/前后端互通** → GeoJSON / WKT（坐标但标准）。
* 要**精修、编辑** → 保留 EPS≈2 的多边形；需要光滑就用样条。

因此"不用坐标"是可行的，但本质是把同一圈多边形换成了**掩码、SDF 或曲线**；真正头痛的
"点太多"问题，答案不是抛弃坐标，而是**简化顶点 + 用曲线 + 按用途选编码**。

## 6. 四个层级（level 10/11/12/13）与导出

四张图是**同一岛屿、按 2 倍逐级放大**：`1024 → 2048 → 4096 → 8192`，对应瓦片范围
`508..511 → 1016..1023 → 2032..2047 → 4064..4095`（边界差一个瓦片），完全符合
Web-Mercator 金字塔的翻倍规则。

做了交叉验证：把 level 11/12/13 各缩小到 1024 重新提取外边界，与 level_10 的可通行掩码做
逐像素 XOR 比较，差异约 `0.095% ~ 0.10%`（集中在海岸线抗锯齿边缘）。说明四张图的边界在
归一化坐标下是**同一个形状**，因此各层级坐标可以由 level_10 这份权威多边形乘以 `2^(level-10)` 精确得到。

导出脚本：

```powershell
python tools/export_airwall_levels.py
```

它读取 `assets/mapdata/airwall_level10.json`，为每个目标层级写出
`airwall_level{L}.json / .geojson / .svg / _preview.png`，并保证：

* `image_px` = level_10 的 `(x,y) × 2^k`（打到该层原生拼图上）；
* `world_px_level` = `508·2^k·256 + image_px`（世界像素，跨层级 ×2^k）；
* `tile_px` 用该层瓦片范围重算；`normalized` 与 level_10 完全一致；
* 预览图使用**该层级自己的拼图**做底图（超过 2048 会缩小便于查看，数据仍为原生坐标）。

如果你希望 level 12/13 的轮廓用原生高分辨率重新提取（而非缩放），可在
`tools/extract_map_airwall.py` 里把 `--image` 指向对应拼图并给对 `--level/--tx0/--ty0`；
但 8192×8192 的纯 Python 处理较慢、内存较大，缩放方案在"内容完全相同"前提下已足够精确。

## 7. 怎么在项目里用

```python
import json
data = json.load(open("assets/mapdata/airwall_level10.json", encoding="utf-8"))
pts = data["polygon"]["image_px"]            # 直接叠加到 level_10 图上
world = data["polygon"]["world_px_level"]    # 标准全局像素坐标（层级10）
```

如需层级 11/12/13 的同一条空气墙：把 `image_px` 或 `world_px_level` 整体 `× 2^k` 即可。

重新提取（换阈值 / 换 eps / 换输入图）：

```powershell
python tools/extract_map_airwall.py --image assets/mapsrc/level_10_508_511_508_511.png --eps 3 --outdir assets/mapdata
```

> 提示：想以**淡蓝色浅滩为边**（默认）就保持 `--thresh 70`；
> 想要更靠外（把外圈暗晕也算进地图）就 `--thresh 48`；想要更往里收就用更大阈值。
