# 地图坐标系与小地图定位规则

> 本文定义"大图（level 13 拼图）— 瓦片 — 归一化坐标 — 小地图截图"之间的**统一坐标系**，
> 并说明用于把小地图定位进大图的传统 CV 方案（SIFT/ORB + 归一化互相关）与实测结论。
> 坐标规则 100% 对齐前端 `frontend/src/components/Tool/MapAwareness.tsx` 及
> `frontend/src/data/mapAirwall.ts`，边界逻辑对齐 `docs/map-airwall-coordinate.md`。

---

## 1. 统一逻辑世界坐标（前端实际用的）

前端把整张大地图放入一个**局部世界坐标系**：`WORLD_W = WORLD_H = 8192`，坐标范围 `0..8191`。
这张图就是 `assets/mapsrc/level_13_4064_4095_4064_4095.png`（8192 × 8192）。

前端用三级 LOD 加载瓦片（同一世界、不同清晰度）：

| 层级 | 瓦片范围 | 数量 | 每瓦片在世界中的边长 | 瓦片图宽 |
| --- | --- | --- | --- | --- |
| 11 | tileX/Y ∈ [1016,1023] | 8×8 | 1024 世界px | 256px（每图px=4 世界px） |
| 12 | tileX/Y ∈ [2032,2047] | 16×16 | 512 世界px | 256px（每图px=2 世界px） |
| 13 | tileX/Y ∈ [4064,4095] | 32×32 | 256 世界px | 256px（每图px=1 世界px，1:1） |

世界坐标 `(wx, wy)` ∈ [0,8191] 与瓦片/像素换算（level 13，推荐统一基准）：

```
tileX  = 4064 + floor(wx / 256)
tileY  = 4064 + floor(wy / 256)
tilePX = wx % 256        # 瓦片内像素（0..255）
tilePY = wy % 256

反向： wx = (tileX-4064)*256 + tilePX
```

其它层级反向换算：

```
level 12: wx = (tileX-2032)*512 + imagePX*2
level 11: wx = (tileX-1016)*1024 + imagePX*4
```

前端渲染公式（地图画布）：

```
screenX = screenOffsetX + wx * zoom
screenY = screenOffsetY + wy * zoom
```

### 1.1 与"全球 slippy-map 像素"的关系（可选）

本仓库另一套"全局瓦片像素"约定是 `worldX_global = tileX*256 + inset`。两者只差一个常量偏移：

```
本地世界坐标 wx = worldX_global(level13) - 4064*256 = worldX_global - 1,040,384
```

前端、空气墙、以及本定位方案统一用**本地世界坐标（0..8191）**，避免大数。

## 2. 空气墙 / 可通行边界

前端 `frontend/src/data/mapAirwall.ts` 里的 `AIRWALL_POLYGON_L13` 就是 level 13 空气墙
（448 顶点，THRESH=70 的淡蓝浅滩外沿），坐标就是上面的本地世界坐标 `0..8191`。

* `isPointInPolygon(p)` —— 射线法判定世界坐标点是否在岛屿内。
* `drawSmoothClosedPolygon(...)` —— 闭合二次贝塞尔平滑绘制，`world→screen` 用 `offset + pos*zoom`。

定位时可用它过滤候选框：小地图区域中心必须在空气墙多边形内（否则直接判为无效候选）。

## 3. 小地图（截图）→ 世界坐标 的换算

设通过匹配得出：小地图在世界中的区域为
`center=(cx, cy)`、`regionW = Rw`（世界像素宽）、`regionH = Rh`（世界像素高，允许与宽不同）。

小地图像素 `(sx, sy)`（`0..sw-1, 0..sh-1`）映射到世界坐标：

```
wx = (cx - Rw/2) + sx * (Rw / sw)
wy = (cy - Rh/2) + sy * (Rh / sh)
```

再据 §1 把 `(wx,wy)` 转成瓦片号 + 瓦片内像素、或归一化坐标 `(wx/8192, wy/8192)`。

通常 `Rw ≈ Rh`。玩家位于小地图中心 `(cx, cy)`（截图中玩家箭头在圆心）。

## 4. 传统 CV 定位方案（SIFT / ORB / NCC）

### 4.1 流程
1. 读大图 level 13（8192×8192）与 4 张小地图（约 177–186px）。
2. 小地图预处理：圆形裁剪（外围置中性值）、去 UI 不必要影响、必要时 CLAHE。
3. **方法A SIFT**：对小地图（放大 ×2~4 提升特征）与大图做特征匹配，`BFMatcher` + 比值检验 +
   `estimateAffinePartial2D`（缩放+平移+少量旋转），统计内点。
4. **方法B ORB**：同上，ORB 在 180px 小图上能得到数百个关键点。
5. **方法C 归一化互相关（NCC）**：FFT 加速的掩膜 NCC + 尺度/旋转搜索（对低纹理、晕影最稳）。
6. 用空气墙多边形过滤候选，得到 `(cx, cy, Rw)`，换算成瓦片/归一化坐标。
7. 输出结果图：把小地图贴到大图对应世界位置，并给出置信度。

### 4.2 实测结论（重要）

对 4 张真实小地图，**SIFT / ORB / NCC（含尺度与旋转搜索）均无法把峰值锁定到正确位置**：

| 小地图 | 描述 | 传统 CV 最佳得分 | 定位正确性 |
| --- | --- | --- | --- |
| 1 | 沙漠+绿崖+路+海岸 | ≈0.29–0.34 | 错（匹配到水域） |
| 2 | 绿地+路+建筑 | ≈0.29–0.32 | 错（匹配到沙滩） |
| 3 | 绿地+灰建筑群 | ≈0.30–0.41 | 错（匹配到雪山） |
| 4 | 绿地+灰建筑+路 | ≈0.41 | 错（匹配到雪山） |

对照实验：一张**真实裁剪 + 缩小到 180px + 加径向晕影 + 中心标记**的"模拟小地图"，本 NCC 管线
能正确找回位置（中心误差 ~21 世界px），得分也只有 ~0.34。这说明：

* **得分本身不高不代表没对上**（小图太糊、晕影太重把真实得分也压到 ~0.3）；
* 但真实小地图的**峰值落在视觉明显错误的位置**（沙漠/森林对上水/雪），说明**判别力不足**。

**结论：对这 4 张真实小地图，纯传统 CV（SIFT/ORB/NCC）准确率不达标，不建议据此上线。**
推测原因：小地图渲染与大图 LOD/色调/晕影/水印差异过大，或小地图对应的区域/渲染管线不同。

### 4.3 提高准确率的可行方向
1. 拿到**去 UI、去晕影、去水印**的清晰小地图底图（或用游戏原图自带的裁剪坐标）。
2. 若能确认"小地图=固定世界尺度"（如 Rw 恒定），把尺度固定后 NCC 精度会显著提升。
3. 改用**粗到细**：先按 `Rw` 网格粗定位，再在候选附近细匹配，并用空气墙 + 一致性校验。
4. 小地图若带有朝向旋转，先归一化朝向（如用小地图罗盘指针校平）。
5. 仍不行再考虑轻量可训练匹配（如 DINOv2 特征比对，仓库已有），但成本更高。
